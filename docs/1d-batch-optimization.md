# MUSA S5000 的 1D batch 计划优化

基于 `87b374f`，GPU 基线实现与 `5e0c4bc` 相同。所有实验在独立
`FlagFFT-dev-batch-opt` worktree 对应的远端构建运行。

## 两类慢点及证据

### 16381 点双精度：Rader 的较短卷积不代表更快

原计划是 Rader：16380 点卷积，分解为 36×455，叶因子分别是 `[6,6]`
和 `[13,7,5]`。batch=64 的 Z2Z forward 为 12.736 ms。

改为 Bluestein 后，卷积填充为 32768，分解为 128×256。虽然计算长度变大，
规则叶节点的 GPU 执行更快：仅换算法降到 0.828 ms；进一步复用已有的
chirp/pointwise 边界融合降到 0.527 ms。该消融实验支持“计划选择是主要瓶颈”，
并未直接证明寄存器溢出或某个单独指令是根因。

最终策略限于 MUSA capability 3.1、FP64 输入/输出、16381 点、batch≥16。
8191 点原有策略保留。超过 256 MiB 单卷积缓冲区预算后，仍保留既有分块路径，
不强行启用整批融合。16381 点 FP64 的融合上限因此为 batch=512。

| Z2Z forward batch | 原始 ms | 最终 ms | 优化倍数 |
|---:|---:|---:|---:|
| 16 | 3.20488 | 0.17516 | 18.30× |
| 64 | 12.73608 | 0.52692 | 24.17× |
| 512 | 101.70792 | 3.86860 | 26.29× |
| 4096 | 814.91315 | 46.54776 | 17.51× |

### 131072 点：batch 场景的分解成本估计失准

原计划为 128×1024。固定 batch=64、warmup=10、iters=100，比较四个分解：

| 分解 | C2C forward ms | Z2Z forward ms | D2Z ms |
|---|---:|---:|---:|
| 128×1024 | 0.71044 | 2.27204 | 2.47408 |
| 256×512 | 0.52944 | 1.02732 | 1.01764 |
| 512×256 | 0.52492 | 0.95128 | 0.92952 |
| 1024×128 | 0.70124 | 1.74288 | 1.73988 |

给已测目标的成本模型增加 512×256 偏好，限制为 capability 3.1、131072 点、
batch≥16。沿用成本模型已有的候选惩罚方式；CUDA 及其他长度保持原策略。
实验用强制分解环境变量不进入最终代码。

最终自动策略的 batch=512 成对复测：

| API（forward） | 原始 ms | 最终 ms | 优化倍数 |
|---|---:|---:|---:|
| C2C | 5.29228 | 3.57820 | 1.479× |
| Z2Z | 18.88472 | 7.01132 | 2.693× |
| D2Z | 19.29884 | 6.93156 | 2.784× |

实数路径依旧使用完整长度中间数组。本次修正分解选择，没有实现批量半长度
packed-real。后者涉及批量间距和原地存储布局，需要独立实现及验证。

## 验证与复现

原始数据在主机 `results/20260913_165533_batch_opt/`，每条命令保留 JSON、stderr
和命令参数；`run.py` 串行运行 GPU 测量并逐条 flush/fsync CSV。
`summarize.py` 从成功记录重新生成 `comparison.csv` 和 `REPORT.md`。

- `prime_smoke`：单独替换算法的消融测试及 batch=64 正确性。
- `prime_validate`：最终融合策略在 batch=16/64/512/4096 的性能及 batch=16/512 正确性。
- `split_smoke`：四种分解的独立计时。
- `ct_validate`：最终自动策略的六种 API 性能、正确性，以及 batch=513 的分块尾部检查。
- `final_checks`：最终源码的计划选择回归测试。

性能 Passed 仅代表测量成功，正确性由单独的参考比较和往返测试判断，沿用项目
原有误差与多输入尺度标准。没有降低浮点精度或放宽容差。

最终候选的 29 项实际正确性测试、3 项最终计划选择回归全部通过。
仅换算法的早期消融版本另有 6 项正确性测试通过。CT 的六种 API 在
batch=16/512 共 16 个方向组合均成功测量；16381 的最终候选测量覆盖
batch=16/64/512/4096，完整对照见结果目录。

测量支持上述目标和已测 batch；不据此承诺所有长度、batch 或 GPU 都受益。
A100 的独立补测不作为本次 MUSA 策略的验证依据。
