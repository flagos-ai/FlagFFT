# 1D batch 泛化优化

本轮基于 `1e02124`，将上轮 16381 / 131072 两个规模的选择特判替换为批量实测调优，并扩展偶数实数 FFT 的半长度算法。实验根目录为 `results/20260913_181012_batch_general/`，逐项结果持续写入 CSV。

## 为什么 batch 慢

同样的数学复杂度不代表同样的 GPU 耗时。当前存在三类不同问题：

- 质数选择：Rader 使用 N−1 卷积，Bluestein 使用大于等于 2N−1 的二次幂卷积。前者长度较短，但混合基数子 FFT、排列与访存成本可能更高；不能只比较卷积长度。
- 四步分解：N1×N2 与 N2×N1 数学等价，行/列内核的访问方式、打包和资源占用不对称。batch 放大差异，单 batch 的计划不一定适合大 batch。
- 实数数据：长度 N 的实数 FFT 可以用 N/2 的复数 FFT 加前后处理完成，但子 FFT 分解不佳或额外启动开销较大时，减半也可能变慢。

## 实现

### 算法与分解的实测选择

`flagfft-cli tune` 现在支持 C2C、Z2Z 和任意正 batch。默认计划始终在候选集中；复合数加入不同四步分解，符合现有算法范围的质数加入 Rader/Bluestein。每个候选先比较正逆向平台参考结果，再进行筛选和复测，以两个方向平均中位耗时为目标选择同一个计划。

FP32 沿用原调优器的相对 L2/L∞ 上限 2e-4；新增 FP64 调优门限为 1e-12。独立 correctness 测试仍使用项目自己的精度标准，没有修改测试容差。调优器的比较是数值校验，不是精确算术证明。

例如：

```sh
flagfft-cli tune --api z2z --shape 12289 --batch 64 \
  --max-candidates 3 --finalists 2 \
  --screen-warmup 3 --screen-iters 10 \
  --final-warmup 10 --final-iters 100 --db /path/tuned.sqlite --json
FLAGFFT_TUNE_DB=/path/tuned.sqlite flagfft-cli bench \
  --rank 1 --shape 12289 --batch 64 --api z2z \
  --direction forward --warmup 10 --iters 100 --json
```

调优是显式的一次性操作，包含 JIT 和多个候选的开销。普通计划创建不会自动跑 benchmark。无匹配缓存时使用默认成本模型；`FLAGFFT_TUNE_DISABLE=1` 禁用缓存。

缓存继续区分设备架构、dtype、方向、norm、布局和实现指纹，但 batch 改成精确值，避免把 batch=16 的赢家推广到同一旧 bucket 中的 batch=64。旧指纹失效，需要重新调优。该方法泛化的是候选生成和选择过程，不承诺所有长度共用一种分解，也不承诺有限候选搜索找到了全局最优。

### 批量半长度 real 算法

将实数相邻元素组成 `y[j]=x[2j]+i*x[2j+1]`，计算 N/2 点复数 FFT 后利用共轭对称关系恢复 N 点实数频谱。逆向执行对应重构，再用 N/2 点逆变换。API 仍只接受原有紧密或 Nyquist padding 布局，任意额外 padding 仍返回 NOT_SUPPORTED。数学上保持原变换及非归一化语义。

实现支持独立 batch，保留 compact spectrum 的 batch distance。紧密布局使用半长度路径；原地和需要额外 real 行间距的布局回退原有 distance-aware 路径。回退计划按第一次需要时创建，避免普通紧密布局额外分配整长工作区；因此支持的 Nyquist padding／原地布局首次执行可能包含 JIT/分配，应在计时或捕获前 warmup。

`FLAGFFT_PACKED_REAL=0` 禁用，`1` 强制实验，其他值/未设置为 auto。auto 保持 FP64、S5000/A100、偶数长度和原资源范围约束，批量叶节点采用更保守的上限。FP32 可强制实验，尚未默认启用。

半长度 complex 子计划也查询同一实测缓存，因此可复用针对 N/2、相同 batch 和方向的调优结果，再检查资源范围。强制开启仍可能变慢；它不是所有偶数长度的性能保证。

### Rader DC 复用：删除重复归约

逐内核诊断将 16381 点 S5000 FP64 的主要耗时定位到 finalize，而不是卷积 FFT。旧源码在每个 256 点输出块中都归约整段 N 点输入，只有块 0 写 DC；每个 batch 的额外归约工作约为 `N * ceil((N-1)/256)`。把写入 mask 改成控制流分支虽能减少重复计算，仍保留大归约及其编译资源需求。

最终实现利用 Rader 的数学关系：第一次卷积 FFT 的输入是 `x[1..N-1]` 的排列，因此其零频项 `A[0]=sum(x[1..N-1])`，而原 DFT 的零频项为 `X[0]=x[0]+A[0]`。在已有 pointwise 内核中保存这个结果，finalize 只做非零频点的逐点恢复。DC 的新增工作变成每 batch 常量级，无新增 kernel launch 或工作区；整体 FFT 仍有卷积和逐点排列成本。

该改动没有设备、长度、batch 或精度分支；正逆向都成立。原地执行沿用已有 input copy，避免写 DC 后污染输入 x[0]。C++ pointwise 参数和 Python signature 同时更新，并更新 codegen/runtime 指纹，因此本轮较早保存的调优结果需要在最终代码上重新调优。

### Bluestein 融合与诊断

S5000 FP64 batch 卷积边界融合，改为按叶节点和现有 256 MiB 分块预算判断，移除原始质数 16381 的等值检查。历史 8191 默认算法策略保留；本轮不宣称清除了所有既有平台策略。

`FLAGFFT_PROFILE_KERNELS=1` 在 stderr 输出内核名、网格和 GPU event 时间。该诊断会同步并扰动执行，只用于定位各阶段；正常端到端性能必须在关闭诊断时测量。

## 验证结果

调优实验的默认列是移除两个特判后的通用成本模型。16381/131072 用于证明可复现旧收益，不能把它们再次当作相对上轮优化版本的新增提速。新增泛化收益以其他长度和新 batch 路径为证据。报告还分开列出后续 DC 复用优化的旧库/新库对照与重新调优；不要混用两个阶段的缓存和性能结论。

详见实验目录 `REPORT.md` 与各套件增量 CSV。报告区分强制算法实验、最终 auto、实测缓存重放和诊断计时；保留退化点，不以平均值隐藏反例。

### 已复核的代表性结果

以下均为端到端中位耗时（ms），不是逐内核诊断时间。Rader 行保持 Rader 算法、禁用调优缓存，用隔离的旧库/旧 Python 与新实现比较；real 行比较关闭与 auto 半长度路径。

|---|---|---:|---:|---:|---:|---:|
| S5000 | Z2Z / Rader | 12289 | 64 | 8.715920 | 0.464840 | 18.75× |
| S5000 | Z2Z / Rader | 16381 | 4 | 0.990760 | 0.130080 | 7.62× |
| S5000 | Z2Z / Rader | 16381 | 64 | 12.742360 | 0.715640 | 17.81× |
| S5000 | Z2Z / Rader | 16381 | 512 | 101.731155 | 5.513000 | 18.45× |
| A100 | Z2Z / Rader | 12289 | 64 | 0.475136 | 0.316416 | 1.50× |
| A100 | Z2Z / Rader | 16381 | 64 | 0.605184 | 0.357376 | 1.69× |
| S5000 | D2Z / real | 98304 | 512 | 6.971720 | 5.088440 | 1.37× |
| S5000 | Z2D / real | 98304 | 512 | 7.106520 | 4.827080 | 1.47× |
| A100 | D2Z / real | 98304 | 512 | 3.980288 | 2.323456 | 1.71× |
| A100 | Z2D / real | 98304 | 512 | 3.950592 | 2.418688 | 1.63× |

1009 点、FP32 以及小 batch 的部分 case 改善很小或出现微小反向变化，完整表保留这些控制项。强制半长度并非总是更快：S5000 的 262144 点原始半长度路径明显退化，最终无缓存 auto 按叶资源条件保留原路径。复用实测 child 后 inverse 有收益，但 forward 仍可能略慢；complex 调优不是 real 端到端调优。

本轮不是 592-case 全量重跑，也没有重新扫完 batch=1024/4096；采用新长度、batch=4/16/64/512、六 API correctness、原地/非原地和支持的 padding 验证边界。
